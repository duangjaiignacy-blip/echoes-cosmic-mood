# Echoes 动态黑洞银河背景演示设计规格

状态：已获用户方向确认，待书面规格复核
日期：2026-07-25

## 1. 目标

在不替换 Echoes 正式背景的前提下，增加一个可单独打开的「动态黑洞银河」背景演示。视觉构图参考用户提供的竖版黑洞图：黑色事件视界、银白色倾斜吸积盘、左上方粒子流和深黑星空。动效模型沿用用户给出的 Galaxy 参数：

- `starSpeed={0.7}`
- `density={1.7}`
- `hueShift={140}`
- `speed={1.4}`
- `glowIntensity={0.45}`
- `saturation={0.15}`
- `mouseRepulsion`
- `repulsionStrength={2}`
- `twinkleIntensity={0.4}`
- `rotationSpeed={0.1}`
- `transparent`

## 2. 演示边界

- 默认地址 `http://localhost:5173/` 仍显示现有 Aurora + Starfield 背景。
- 演示地址 `http://localhost:5173/?bgDemo=black-hole` 在同一产品页面启用动态黑洞背景。
- 演示模式下隐藏 Aurora 和旧 Starfield，避免双重星空。
- 不添加可见的演示按钮、标签或调试面板，使用者看到的是真实产品叠加效果。
- 本阶段不将演示背景设为默认，也不删除旧背景组件。

## 3. 组件与渲染架构

### 3.1 React 边界

新增 `BlackHoleGalaxy` 组件，作为全屏 Canvas 的 React 生命周期容器。组件只负责：

- 创建和销毁渲染器。
- 把用户给出的参数传入 uniform。
- 监听窗口或容器尺寸。
- 监听指针位置，但不拦截点击、拖动和页面滚动。
- 在 WebGL 失败时切换至 CSS 降级背景。

### 3.2 WebGL 渲染器

使用项目已有的原生 WebGL 模式，不引入 OGL、Three.js 或静态图片依赖。渲染器拥有一个全屏四边形、一个着色器程序、一个缓冲区和一个 `requestAnimationFrame` 循环。渲染 DPR 上限为 1.5，降低全屏片元着色器的移动端成本。

## 4. 视觉形状

片元着色器不绘制通用旋涡星系，而是按参考图生成以下层次：

1. **深黑基底**：接近纯黑，仅在吸积盘附近带很弱的冷蓝色。
2. **事件视界**：画面水平居中，移动端位于约 `47%` 的垂直位置；使用深黑软边圆盘与周边引力暗化表现。
3. **银白吸积环**：以椭圆距离场生成高亮内环和多层细丝，整体向右下倾斜约 `18°`。
4. **弯曲光带**：用极坐标噪声和半径扭曲生成围绕视界旋转的亮丝，不使用一张静态贴图。
5. **左上粒子流**：从吸积盘的左上切线向画面外延伸，密度逐渐衰减。
6. **背景星点**：使用多层深度、不同尺寸和亮度，保留大片纯黑负空间，不绘制紫色星云。

`hueShift=140` 只用于星点与高光的很弱冷色偏移；`saturation=0.15` 使整体仍以银白和黑色为主，不将黑洞染成高饱和彩色。

## 5. 动效与交互

- `rotationSpeed=0.1` 控制吸积盘的缓慢旋转和内部亮丝流动，事件视界不平移。
- `speed=1.4` 控制噪声与粒子流的时间速率。
- `starSpeed=0.7` 控制背景星层的深度漂移。
- `density=1.7` 控制星点与吸积盘细丝密度，但不影响事件视界尺寸。
- `glowIntensity=0.45` 只提升高亮环和亮星，不提高全屏黑位。
- `twinkleIntensity=0.4` 为星点添加不同步的微弱闪烁。
- 指针进入页面时，星点和吸积盘外层尘埃在指针周边平滑排斥；黑洞核心与主光环不变形，避免整个构图被鼠标拉散。
- Canvas 使用 `pointer-events: none`，鼠标坐标由 `window` 或 `.stage` 监听，产品按钮和拨盘仍可操作。
- `prefers-reduced-motion: reduce` 时冻结时间和闪烁，保留一帧完整黑洞图像。

## 6. 响应式与内容可读性

- 移动端使用竖版构图：黑洞位于画面中部，粒子流向左上延伸，吸积盘向右下穿出画面。
- 桌面端不拉伸移动构图：着色器按宽高比扩展星空和光带，事件视界保持圆形。
- 在 Canvas 与产品内容之间保留一层低强度的透明黑色遮罩，仅用于保证标题、弱提示文字和按钮边界可读，不遮住吸积盘主体。

## 7. 降级与故障处理

- WebGL 创建、着色器编译或链接失败时，显示 CSS 黑洞降级层：黑色背景、暗色事件视界与一条银灰色椭圆光环。
- `webglcontextlost` 发生时停止动画、解绑监听器并切换降级层。
- 故障不影响业务页面、拨盘、按钮或 ACP 服务。

## 8. 验证与验收

1. 先编写着色器接口、参数归一化、DPR 上限、编译失败和降级行为的失败测试。
2. 默认 URL 的 DOM 中不存在黑洞 Canvas，旧 Aurora 和 Starfield 仍存在。
3. `?bgDemo=black-hole` 的 DOM 中存在一个处于 `webgl` 状态的全屏 Canvas，旧背景不同时渲染。
4. 移动端 445×805 截图中可明确识别出黑洞、倾斜吸积盘、左上粒子流和黑色负空间，构图接近参考图。
5. 桌面端 1280×900 无拉伸、无横向溢出，事件视界保持圆形。
6. 鼠标移动前后粒子层发生可见变化，主黑洞中心位置不变。
7. 减少动效模式的稳定帧明显比正常模式更接近静止。
8. 强制上下文丢失后降级层可见，产品交互仍可用。
9. `npm test`、`npm run build`、`npm run lint` 和 `git diff --check` 全部通过。

## 9. 正式替换门槛

演示完成后，只向用户提供演示 URL 和截图/验收结果。未获得用户对演示效果的再次确认前，不将黑洞背景设为默认，不删除现有背景实现。
